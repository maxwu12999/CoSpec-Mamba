# 当前210项队列的独立加速入口

把本目录放在 `src/cospec_speedup_v1`，与原来的 `src/cospec_full_lr001_v1` 并列。保留原目录、数据和 diagnostics。无需重新安装依赖。

在服务器的 src 目录执行：

```bash
python -m zipfile -e cospec_speedup_v1.zip .
bash cospec_speedup_v1/start.sh
```

启动器会请求原任务保存当前完整训练轮或测试批次，等待真实工作锁释放，再以后台方式接续同一队列。保存、打包和等待期间可能需要几分钟。不要另开第二个队列。已完成项会跳过，训练继续读取原 last.pt，测试继续读取各条件的原游标。默认仍为动态显存调度、最多10路；界面仍显示总数、完成数、当前任务和预计剩余。

## 实际改动

- 批量生成图块代替逐个 Python 拼接；训练旋转仍按原顺序逐次抽取随机数。
- CPU 最多预取一批，训练轮结束先等待预取线程，保持检查点中的随机状态。
- 测试同一批图块准备和传输一次，依次执行16套原掩码；模型前向仍为原测试 batch 128。每个条件保留独立统计、预测文件和断点。
- 科学实验代码不改写；仍为原模型、原数据划分和掩码、100轮、固定学习率0.001、训练batch32、测试batch128。没有增加正式训练任务。
- 源码与运行扩展信息留在输出目录并随结果ZIP归档。

## 当前显卡上的自动检查

首次启动先让旧工作进程退出，随后用独立子进程在当前GPU做少量新旧对照：HongHu的D与ConvMamba_aug，各1024个测试点，16个条件，旧/新/新/旧各执行一次。它不修改正式训练权重，也不把这些小样本结果当正式精度结果。

检查训练输入与随机状态、逐条件预测/混淆矩阵/置信度及权重未改变；确认样本测试耗时至少降低约2%且显存增长在限定范围内，才启用新入口。不兼容或没有测到收益，就继续原入口。该检查通常需要几分钟，具体取决于服务器。它只衡量测试子集，不能保证整条队列加速相同倍数。

详情日志：`src/diagnostics/COSPEC_FULL_LR001_V1/speedup_benchmark.log`。
新旧入口共享原协议ID与结果目录，不重复已完成任务。运行扩展记录位于输出的 `runtime_speedup` 目录。

## 控制和回退

原目录的 watch.sh、stop.sh 和 control.py 仍可使用。调整上限仍使用原 control.py slots 命令，上限不超过10。

从src目录回到原入口：

```bash
bash cospec_speedup_v1/rollback.sh
```

回退同样先保存并等待旧进程退出，然后读取同一断点；不会删除加速期间已完成的结果。

使用其他输出路径、参考目录或窗口配置时，启动和回退均传入与原队列一致的参数。当前用户的默认210项队列无需另传参数。

## 验证范围

见 VALIDATION.md 与 verification 日志。开发环境完成了CPU一致性和进程恢复验证；没有在开发环境的真实CUDA卡上预先计时，实际GPU对照由上述自动检查执行。GPU原有非确定性算子仍有原来的数值限制。
