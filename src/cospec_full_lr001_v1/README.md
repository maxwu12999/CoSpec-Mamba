| 范围 | 次数 |
|---|---:|
| 原COSPEC_SUITE_V1完整99项，原数据集/模型/种子范围不变 | 99 |
| 原COSPEC_EXTERNAL_V1完整105项，7数据集×5外部模型×3种子 | 105 |

每次训练后，测试完整输入，以及80%、60%、40%、20%、10%保留率。每个缺波段保留率3套共享掩码，共16种条件，210项合计3360组测试。20%和10%不额外训练，不把训练样本数量减少成20%或10%。

原99项中，ConvMamba_aug/B/D在7个数据集各3种子；A/C和扫描、结构消融仍在HongHu/PaviaU各3种子。没有把原来两数据集的消融偷偷扩大到七数据集。9×9按现有论文窗口表补HongHu，与15×15主表分开汇总。

## 在AutoDL启动

将cospec_full_lr001_v1整个文件夹解压到原项目src下：

`/root/autodl-tmp/hsi-work/ConvMamba-main/src/cospec_full_lr001_v1`

默认读取相邻原99项目录的数据缓存：

`src/diagnostics/COSPEC_SUITE_V1/cache/<数据集>/`

需要保留7个数据集的cube.npy、tr.npy、te.npy、wave.npy、stats.npz和data.json。只需要旧数据缓存，不需要旧模型权重；源码及上游模型已随本包提供。程序会核对所有缓存哈希，不重新划分，不下载数据，不升级依赖。

```bash
cd /root/autodl-tmp/hsi-work/ConvMamba-main/src/cospec_full_lr001_v1
bash start.sh
```

start.sh在没有激活其他venv时自动使用`/root/autodl-tmp/venvs/cospec/bin/python`；也可先手动激活正确的环境。所需依赖与之前环境一致：torch、mamba-ssm、causal-conv1d、numpy、einops、Pillow。MiM采用已验证的cuda_fused扫描适配，其他模型保持归档实现。

启动后自动检查数据、PCA和当前GPU上各模型/输入规模的显存峰值，然后后台运行并显示精简面板：

- 总任务数。
- 已完成数，指一项100轮训练、16种条件测试及该项导出全部完成。
- 当前并行数及具体数据集、模型、种子、窗口。
- 预计剩余时间，按实际总吞吐更新。预检初期显示待测。

不把10路简单视作10倍加速。各模型速度和测试像元数不同，ETA使用显存预检的分模型成本及运行后的实际总进度校准，初期或换模型时可能波动。

详细epoch、损失、错误及逐批进度在新输出目录logs里，不刷主界面。退出查看窗口的Ctrl+C只退出面板，后台继续。关闭网页终端也不停止后台训练。

```bash

# 只看一次状态
python status.py
```

没有人为规定跑到75停止，这次默认执行完全部210项。若想限制并行，例如最多6路，可用`bash start.sh --max-parallel 6`首次启动，或运行中执行`python control.py slots --max-parallel 6`。当前已启动的任务不会被强杀，完成后逐步降到新上限。硬上限始终不超过10。

## 显存与恢复

显存预检包含真实训练batch32的完整/缺波段双视图反向、Adam更新，以及测试batch128的完整和10%输入。预检独立进程结束释放显存，每种兼容模型/输入签名保存峰值。正式运行预留峰值安全余量及至少1GiB全卡余量，并预约仍在初始化任务的未来显存，避免同时启动多个任务造成挤占。检查RAM可用量，不复制所有图块。

预检会等待显卡上其他计算进程退出，并检查剩余显存；等待和预检期间都可用停止脚本退出。RAM保护同时读取宿主机可用内存和容器内存上限，采用较小者。单项峰值加安全余量超过全卡容量时会明确阻塞，不能通过增加并行解决。

当有任务完成或进入较轻阶段，调度器会尝试启动能放下的后续任务，避免被队首大模型堵住。最多10路是上限，显存不足时会保持较少并行。若仍发生OOM，会保留已保存断点、修正峰值估计并降低并行重试；必要时该任务单独运行。不自动改变训练batch或学习率。

OOM修正和独占重试标记均落盘。重启时，若修正后的保守预约已大于整卡容量，也会改为独占尝试，不会永久等待一个不可能满足的预约。连续失败仍会记录为失败项，不计入完成。

每完整epoch保存模型、Adam状态和所有训练随机状态。测试每50个batch及安全停止时保存像元游标、预测和累计指标，可从当前条件断点继续，不必重测整幅影像。强制关机可能重做最后未保存的一轮或至多50个测试batch。通过停止脚本退出通常只需完成当前轮或当前batch。

本队列使用独立进程锁，重复启动不会重复训练。同一调度器意外退出后，重启会识别仍在运行的本队列工作进程并接管；不会按python进程名停止其他人的任务。新训练结果不会覆盖旧99项、105项、低保留率或学习率验证结果。

新结果只复用本次固定0.001协议的断点；旧“前72轮/后28轮”权重不作为本次完成结果。

## 首版代码包的审计更新

本次修订只修复调度、预检停止、结果验收和界面；模型、训练、掩码和指标算法未改。已开始使用本包首版固定0.001训练时，先运行旧目录的`bash stop.sh`，等待显示已安全停止，再用新版覆盖代码目录，按原命令启动。保留整个新输出目录，不能删除runs、config.json或preprocessing。

程序仅对白名单中的本包首版自动保留协议身份：核对模型/数据文件和训练、测试、统计函数的内容，并确认全部科学配置一致，才沿用检查点；配置先备份，不改写结果和last.pt。运行代码版本另记入environment.json。其他旧实验或不同设置不会被自动接纳。

调度器意外退出时，面板会说明中断并核对仍持有工作锁的进程，不把旧快照当成当前进度。全部任务已完成后再次启动只汇总打包，不再为已完成项运行显存预检。

## 统计与导出

默认输出：`src/diagnostics/COSPEC_FULL_LR001_V1/`

- `summary.csv/json`：每数据集/模型/窗口/保留率，3个训练种子的均值与样本标准差；不足3种子明确标记未齐。
- `metrics_by_seed.csv`：先对每个种子内3套掩码平均的指标。
- `metrics_raw.csv`：全部原始条件指标。
- `runs/patch_015/...`和`runs/patch_009/...`：完整逐轮记录、last.pt、16条件预测及指标。
- `maps/`：种子1在完整/80/60/40/20/10%的第1套掩码分类图及错误图，仅覆盖原TE中心。
- `features/`：同一固定类别均衡TE坐标的特征，最多50/类，可用于后续t-SNE等CPU分析。
- `profiles/`：当前GPU上的调度用峰值与时间样本。它们不是训练后权重的论文公平测速，不能将并行耗时当作单模型效率排名。
- `initialization.json`：各模型参数量和初始权重哈希，B/D等另含共同主干哈希。
- `failures.json`、`logs/`：失败原因及详细日志，不会将失败项算作完成。

结束或安全停止后自动生成3个ZIP：

- `COSPEC_FULL_LR001_V1_results.zip`：统计、指标、逐轮记录、协议及代码。
- `COSPEC_FULL_LR001_V1_maps.zip`：分类图。
- `COSPEC_FULL_LR001_V1_features.zip`：特征。

结果ZIP不包含.pt和整幅影像；所有last.pt仍保存在服务器runs中。以后需要额外条件补测时使用这些权重。

## 路径及窗口选项

原缓存不在相邻位置时，使用`bash start.sh --reference /实际目录/COSPEC_SUITE_V1`。新输出可通过`--output`指定。迁移到另一路径后，缓存内容及科学协议一致即可自动适配路径；GPU变化会重新校准显存，不承诺跨GPU逐位一致。

默认只新增要求中的9×9。原7×7/11×11仍是旧学习率协议；如果后续要把整个窗口表也统一重跑，可首次启动时选择下面的222项方案（比默认多12次训练），不要将不同学习率的窗口结果直接当成同条件比较：

```bash
bash start.sh --windows 7 9 11 --output ../diagnostics/COSPEC_FULL_LR001_ALLWINDOWS
```

已建立的210项输出不能混入222项配置，请用新目录。改变测试batch需显式`--eval-batch`并保持独立配置；默认128。不提供自动降低batch后混入同一协议的行为。

可选`bash check.sh`只完成数据/GPU预检，之后同一参数`bash start.sh`启动。可选`bash smoke.sh`运行合成输入的CPU恢复检查及实际模型GPU数值检查。正常start已自动执行当前真实数据维度的数值/显存预检，不强制重复跑smoke。
